# AGRIFLOW — ESP32 Smart Irrigation with a Live Cloud Dashboard

AGRIFLOW is an ESP32-based smart plant-watering system built for an
Engineering Clinics project at VIT-AP. A soil-moisture sensor and a DHT11
watch the plant, the board drives a water pump, and everything is visible
and controllable from a cloud dashboard on your phone.

**Live dashboard:** https://agriflow-kunal4060s-projects.vercel.app

```
Phone hotspot ──WiFi──> ESP32 ──HTTPS REST──> Firebase RTDB ──live──> Dashboard (Vercel)
   (STA mode)            (GPIO 34/14/25…)      /agriflow/live        /agriflow/control
                                                    /agriflow/history   (pump / mode / thresholds)
```

## Hardware

- ESP32 Dev Module; soil-moisture sensor on GPIO 34, DHT11 on GPIO 14
- Pump (relay) on GPIO 25, buzzer on GPIO 26, buttons on GPIO 32/33
- WiFi LED GPIO 2, Mode LED GPIO 15, OLED SSD1306 128x32 @ 0x3C
- Calibration: wet 1050 / dry 3050. AUTO: pump ON below 30% moisture,
  OFF above 50%. Pump failsafe: 120 s max run, 60 s cooldown.

## How it works (short version)

- The board joins your phone hotspot (STA mode) and pushes live readings
  to Firebase Realtime Database every 10 s (`/agriflow/live`), plus a
  history sample every 60 s (`/agriflow/history`).
- The dashboard reads the live state and sends commands back; the board
  polls `/agriflow/control` every 3 s. In MANUAL mode the pump follows the
  dashboard; in AUTO mode the board's own 30/50 thresholds drive the pump.
- If the hotspot drops, the board falls back to its own Access Point
  (`ESP32_Plant_System`, local page at http://192.168.4.1) and keeps
  watering locally — the cloud is never required for the plant to survive.

## Before you compile — credentials

The sketch ships with placeholders where your hotspot goes:

```cpp
const char *HOTSPOT_SSID = "YOUR_HOTSPOT_SSID";
const char *HOTSPOT_PASS = "YOUR_HOTSPOT_PASSWORD";
```

Put your own hotspot name and password there before uploading. Never
commit your real hotspot password to a public repo. The Firebase web
config in `dashboard/config.js` is public by design (it is already live
on the dashboard) — but the database is in Firebase **test mode, and
those rules EXPIRE on 2026-11-24**. After that date Firebase blocks all
access until the rules are updated in the console (Realtime Database →
Rules). See the note under "Firebase project" below.

## Setup

### 1. Fill in the hotspot (2 lines, top of the .ino)
Open `firmware/Code_ESP32_Plant_Watering_V3.ino` and set:
```cpp
const char *HOTSPOT_SSID = "YourHotspotName";
const char *HOTSPOT_PASS = "YourHotspotPassword";
```
The Firebase host is already set. Nothing else to fill in.

### 2. Arduino IDE — upload
- Board: **ESP32 Dev Module**. Libraries (Library Manager):
  Adafruit SSD1306, Adafruit Unified Sensor, DHT sensor library
  (Adafruit), AceButton (bxparks), **ArduinoJson (Benoit Blanchon — NEW in V3)**.
  (WiFi, WebServer, HTTPClient, WiFiClientSecure ship with the ESP32 package.)
- Upload, open Serial Monitor at 115200.

### 3. Turn on the phone hotspot
The board joins it within ~20 s. Serial shows `connected` + the board IP.
If the hotspot is off, the board runs its own AP again
(`ESP32_Plant_System` / `12345678`, local page at http://192.168.4.1) —
exactly like V2.6. WiFi LED (GPIO2): solid ON = online, slow blink = AP-only.

### 4. Check Firebase (phone/laptop browser)
Open the database in the Firebase console — `/agriflow/live` should update
every 10 s, `/agriflow/history` gets a sample every 60 s.

### 5. Dashboard (live)
The dashboard is deployed on Vercel: https://agriflow-kunal4060s-projects.vercel.app
(`dashboard/` is a static site: `index.html`, `app.js`, `config.js`).
`config.js` already has the real Firebase values, so no further config is
needed. The page shows a "not configured" banner only if the Firebase SDK
fails to load (no internet) — with real data it shows LIVE and updates in
real time.

## How it works

- **Push (board → cloud):** every 10 s the board PUTs `/agriflow/live`:
  `{moisturePct, moistureRaw, temperature, humidity, pumpOn, mode, updatedAt}`.
  Every 60 s it POSTs a sample to `/agriflow/history` (for the chart).
- **Control (dashboard → board):** the board GETs `/agriflow/control`
  every 3 s: `{pump:"on"|"off", mode:"auto"|"manual",
  onThreshold:30, offThreshold:50}`. MANUAL mode → the pump follows
  `control.pump`; AUTO mode → the board's own thresholds drive the pump
  (cloud pump commands are ignored in AUTO, same as the local page).
  Thresholds from the cloud override the 30/50 defaults (validated 0–100,
  ON < OFF).
- **Offline safety:** if the hotspot drops, cloud calls stop and the board
  keeps working locally (sensors, AUTO logic, OLED, buttons, local page).
  The local pump logic NEVER depends on the cloud.
- **Dashboard honesty:** it only ever shows state the board confirmed
  (from `/live`). A control tap sends the command and waits for the
  board's next update — it never paints a guess. If the board stops
  pushing for 30 s, the page switches to OFFLINE.

## Test checklist (hardware)

1. Hotspot ON → upload → Serial shows `connected` → `/agriflow/live`
   appears in Firebase within ~10 s.
2. Dashboard (after Vercel deploy) shows the same moisture % as the OLED.
3. Dashboard MANUAL + Pump ON → motor starts within ~3 s; Pump OFF → stops.
4. Dashboard AUTO + thresholds 30/50 → dip probe in water → motor stops
   in ~2–4 s (same as the V2.6 retest).
5. Hotspot OFF → board falls back to AP → local page at 192.168.4.1 works.
6. Hotspot back ON → board reconnects and resumes pushing (no reboot needed).

## Known limitations (honest)

- The Firebase calls use `setInsecure()` (no certificate check) and the
  database is in open test mode — fine for a college demo, not for
  anything private. See the expiry warning above.
- Each HTTPS round-trip briefly blocks the loop (TLS handshake on the
  first call, then a reused connection). The local page may answer a beat
  slower while a cloud call is in flight; watering logic is unaffected.
- `/agriflow/history` grows by one sample a minute and is not trimmed on
  the device — prune it in the console now and then. The dashboard only
  ever reads the last 50.
- `updatedAt` is seconds since the board booted (no clock/NTP); the
  dashboard shows "updated Xs ago" from when each reading arrived.
- The .ino was statically verified (see below) but NOT compiled here — no
  Arduino toolchain in this VM. Compile once in the Arduino IDE before
  the demo; that is the normal workflow for this project.
